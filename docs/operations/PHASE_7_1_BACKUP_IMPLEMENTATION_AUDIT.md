## 1. Executive Summary

This audit critically evaluates the backup and restoration tooling implemented in Phase 7 (`backup_database.py` and `restore_database.py`). 

The previous test restored 15 tables and 504 rows into SQLite in approximately 0.056–0.061 seconds. While this verified JSON data serialization and basic tabular mapping, **it did not constitute a complete PostgreSQL/Supabase disaster recovery demonstration**. SQLite lacks PostgreSQL extensions, custom schemas (`auth`, `storage`), PostgreSQL-native RLS evaluation, UUID/JSONB indexing, and PL/pgSQL triggers.

This audit establishes the baseline facts regarding what the current tooling captures, what it omits, and how true PostgreSQL disaster recovery must be conducted.

## 2. Fifteen-Point Technical Audit

| # | Question | Current Tooling State (`backup_database.py`) | Technical Assessment & Gap Analysis |
| :---: | :--- | :--- | :--- |
| **1** | **What data is actually exported?** | Exports row-level records from 15 specified tables in `public` schema into a structured JSON file. | Captures user profiles, stations, devices, telemetry readings, alerts, events, outbox deliveries, and worker heartbeats. |
| **2** | **Is the schema included?** | **Partially**. Only extracts column names and basic SQL data type strings from `information_schema.columns`. | **GAP**: No formal DDL (`CREATE TABLE`), column constraints (`NOT NULL`, `DEFAULT`, `CHECK`), or PostgreSQL-specific data types (`uuid`, `timestamptz`, `jsonb`, `numeric(8,4)`) are emitted. |
| **3** | **Are all table records included?** | **Yes** (for the 15 tables listed in `TABLES_TO_BACKUP`). | All current rows in the active `public` application tables are serialized. |
| **4** | **Are sequences included?** | **No**. | **GAP**: Identity sequences (`GENERATED BY DEFAULT AS IDENTITY` or `SERIAL`) are not backed up. Restoring without resetting sequence counters would cause duplicate primary key collisions. |
| **5** | **Are indexes included?** | **No**. | **GAP**: Primary key indexes, unique constraints, and composite performance indexes (e.g., `idx_sensor_readings_station_quality_created`) are not included in the JSON dump. |
| **6** | **Are foreign keys included?** | **No**. | **GAP**: Foreign key constraints are omitted from the export. The restore script only ran non-enforcing post-hoc `SELECT` queries in SQLite. |
| **7** | **Are functions and triggers included?** | **No**. | **GAP**: PostgreSQL triggers (such as `set_updated_at()` and audit log dispatchers) and custom stored procedures are not captured. |
| **8** | **Are RLS policies included?** | **No**. | **GAP**: Critical security policies (`CREATE POLICY ... ON public.system_alerts ...`) are omitted. In a naive restore, tables would either default to public access or block all queries. |
| **9** | **Are grants and roles included?** | **No**. | **GAP**: Permissions granted to Supabase default roles (`anon`, `authenticated`, `service_role`) are omitted. |
| **10** | **Is migration history included?** | **No**. | **GAP**: Supabase migration tracking (`supabase_migrations.schema_migrations`) is not in `TABLES_TO_BACKUP`. |
| **11** | **Are Auth users handled?** | **No**. | **GAP**: The `auth.users` table is in the internal `auth` schema. The tool only exported `public.profiles`. Without `auth.users`, authenticated citizens and officers cannot log in. |
| **12** | **Are Storage bucket definitions handled?** | **No**. | **GAP**: Bucket records in `storage.buckets` (`pollution-evidence`, `public = False`) are not backed up. |
| **13** | **Are actual Storage objects backed up?** | **No**. | **GAP**: Binary evidence files (photographs, PDFs) stored in Supabase Storage are not backed up. Only URL references in `pollution_reports` are saved. |
| **14** | **Are model artifacts included?** | **Backed up separately via Git/Filesystem**. | Model files (`.pkl`, `.json`) reside on the filesystem and are version-controlled in Git, not bundled into the database export. |
| **15** | **Are failed or partial backups detectable?** | **Partially**. | Computes a final SHA-256 hash of the JSON text. However, a table query failure caught by `except Exception` only logged a warning and saved an empty list, which could silently produce a partial backup. |

## 3. Re-classification of Previous Benchmarks

- **Previous Metric**: ~0.056s – 0.061s.
- **Accurate Re-classification**: **JSON Data Serialization Smoke Benchmark**.
- **Correction**: This duration measured local in-memory SQLite table creation and bulk insertion of 504 rows. It **must not** be represented as the application Recovery Time Objective (RTO).
- **True Application RTO**: Must encompass PostgreSQL schema generation, constraint and index building, data loading, Storage/Auth reconciliation, and Flask API readiness probe verification.
